# Chart Digitizer

Chart Digitizer — настольное приложение для ручного извлечения числовых данных
из изображений двумерных графиков. Оно подходит для случаев, когда исходная
таблица недоступна, а положение каждой точки требуется проверить на самом
изображении.

Приложение рассчитано на управляемую ручную работу, а не на автоматическое
распознавание графика целиком. Пользователь задаёт область построения, строит
калибровку осей и подтверждает положение данных. Лупа, субпиксельные координаты
и диагностические показатели позволяют видеть, какое значение будет сохранено,
и вовремя обнаруживать неточную установку опор.

![Калибровка по опорным точкам с контролем согласованности](docs/images/calibration.png)

## Возможности

- линейная и логарифмическая калибровка каждой оси;
- независимые опоры X и Y, а также опоры с двумя известными координатами;
- автоматический поиск прямоугольной области построения с обязательной ручной
  проверкой;
- режим `Scatter` для отдельных маркеров и режим `Curve` для однозначных
  зависимостей `y(x)`;
- точное перемещение точек мышью, клавишами со стрелками и через таблицу;
- лупа, привязка к центру пикселя и подтверждаемый поиск центра маркера;
- несколько серий данных, отдельные стили точек и кривых;
- сохранение рабочего проекта и экспорт результатов в книгу Excel;
- изменяемая по ширине панель инструментов, которую можно скрыть или вынести
  в отдельное окно.

## Требования и запуск

Требуется Python 3.10 или новее. Текущая версия проверяется на Windows 10 и
Windows 11.

```bash
git clone https://github.com/ChumarinGA/Chart-digitizer.git
cd Chart-digitizer
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m src.main
```

После установки проекта как пакета доступна команда `chart-digitizer`:

```bash
python -m pip install .
chart-digitizer
```

## Рабочий процесс

1. Нажмите `Open` или перетащите изображение PNG или JPEG в окно.
2. В режиме `Crop` задайте границы области построения и нажмите
   `Confirm area`.
3. В режиме `Ref Points` выберите типы шкал, расставьте опоры, введите
   известные значения и нажмите `Build`.
4. В режиме `Data Points` выберите `Scatter` или `Curve` и добавьте данные.
5. Проверьте активные точки в лупе и при необходимости уточните их положение.
6. Выберите способ формирования общего листа и нажмите `Export to Excel`.

Кнопка `Panel` или сочетание `Ctrl+B` полностью скрывает панель инструментов.
Её границу можно перетаскивать мышью. Кнопка `Detach panel` выносит панель в
отдельное окно; освободившееся место занимает изображение.

## Область построения

Режим `Crop` не изменяет исходный файл. Он задаёт прямоугольник, внутри которого
можно размещать опоры и точки данных.

Кнопка `Auto-detect area` сначала ищет длинные горизонтальные и вертикальные
линии, затем прямоугольные контуры. Если эти способы не сработали, используется
ограничивающий прямоугольник небелых пикселей. После грубого поиска каждая
сторона уточняется по локальному профилю темноты: выбирается средняя линия
штриха, а не один из его краёв.

Автоматический результат всегда является кандидатом. Подписи, внутренняя
сетка, открытые оси и линии данных могут быть приняты за границу, поэтому перед
подтверждением нужно проверить все четыре стороны при большом увеличении.
После `Confirm area` жёлтая граница остаётся видимой в следующих режимах, но её
заливка отключается и не меняет вид исходных пикселей.

## Как строится калибровка

Калибровка выполняется отдельно для X и Y. X-опора использует только
горизонтальную пиксельную координату, Y-опора — только вертикальную. Опора
`Both` участвует в обеих независимых моделях и подходит для пересечения сетки
или угла рамки, где точно известны оба значения.

Математический минимум:

- две различные пиксельные позиции и два различных значения по X;
- две различные пиксельные позиции и два различных значения по Y.

Обычно это четыре опоры: две `X anchor` и две `Y anchor`. Двух опор `Both`
достаточно только тогда, когда в каждой известны X и Y, причём позиции и
значения различаются по обеим осям. Опоры следует выбирать как можно дальше
друг от друга: одинаковая ошибка установки меньше влияет на масштаб при
большом расстоянии между крайними опорами.

### Математическая модель

Для каждой опоры известно значение оси `v` и измерена пиксельная координата
`p`. В линейной шкале используется `u = v`, в логарифмической —
`u = log10(v)`. Логарифмическая шкала принимает только положительные значения.

Методом наименьших квадратов строится зависимость

```text
p = a · u + b
```

То есть регрессия предсказывает пиксельную координату по известному значению
оси. Такое направление выбрано потому, что основная неопределённость возникает
при установке опоры на растровом изображении. При извлечении данных зависимость
обращается: по пиксельной координате вычисляется `u`, а для логарифмической
шкалы затем восстанавливается `v = 10^u`.

Вычисления выполняются относительно средних значений и нормируются по
диапазону. Это уменьшает потерю точности при больших числах, но не меняет саму
линейную модель. Дополнительные опоры не превращают калибровку в полином:
для каждой оси по-прежнему строится одна прямая в линейном или логарифмическом
пространстве.

### Сколько опор использовать

Две опоры задают прямую точно. Поэтому при двух опорах показатель остатка равен
нулю и ничего не говорит о качестве их установки.

При трёх и более опорах на ось приложение показывает `RMS`
(среднеквадратическое отклонение), максимальный остаток в пикселях и номер
строки с наибольшим отклонением. На практике удобно использовать от трёх до
пяти хорошо разнесённых опор на каждую ось.

Остатки показывают согласованность опор с выбранной моделью. Это не полная
оценка погрешности результата: одинаковое систематическое смещение всех опор
может дать малый остаток. Предупреждение при отклонении более 0,75 пикселя —
ориентир интерфейса, а не универсальная граница допустимой ошибки.

Любое изменение положения или значения опоры, границ области либо типа шкалы
сбрасывает прежнюю калибровку. До повторного нажатия `Build` устаревшее
преобразование не используется.

### Быстрая калибровка по рамке

Если подтверждённые границы проходят по средним линиям прямоугольной рамки,
можно ввести левое и правое значения X, нижнее и верхнее значения Y, затем
нажать `Create anchors and build`. Будут созданы две опоры `Both` в
противоположных углах.

Этот способ быстр, но две опоры на ось не дают диагностических остатков. Для
ответственной работы полезно добавить промежуточные опоры и проверить их
согласованность.

## Где находится центр толстой рамки

Пиксель изображения рассматривается как квадрат. Центр пикселя с номером `n`
имеет координату `n + 0,5`. Если штрих занимает четыре соседних пикселя от `j`
до `j + 3`, его геометрическая середина находится в `j + 2` — между центрами
двух средних пикселей.

Поэтому на рамке толщиной 4 пикселя пересечение крестика нужно ставить на
среднюю линию штриха, а не на внутренний или внешний край и не обязательно на
центр отдельного пикселя. Координаты в приложении непрерывные: средняя линия
сглаженного или неравномерного штриха может иметь произвольную дробную часть.

Флажок `Snap anchors to stroke centre (±10 px)` помогает при создании опоры.
Для X-опоры он ищет центр ближайшего тёмного вертикального штриха, для Y-опоры
— горизонтального. При недостаточном контрасте исходная координата остаётся
без изменений. Инструмент не исправляет наклонённые оси и не заменяет
визуальную проверку в лупе.

## Лупа и активная точка

Лупа следует за сохранённым центром активной точки, а не за курсором. Активной
становится новая точка, точка, выбранная на изображении, или строка таблицы.
Красный крест в лупе показывает координату, которая попадёт в проект и будет
использована при экспорте.

Изображение в лупе увеличивается без сглаживания: видны исходные пиксели, а
промежуточные цвета не создаются. Подпись сообщает, находится ли крест в центре
пикселя или на границе между пикселями.

В `Scatter` и `Curve` активная точка выделяется цветным контуром, крестом и
полупрозрачной заливкой. Параметр `Active fill opacity` в окне `Style Points`
задаётся отдельно для каждого режима. Он влияет на отображение любой точки,
когда она становится активной, но не меняет её координаты.

![Настройка вида активной точки](docs/images/active-point-style.png)

## Два инструмента центрирования

`Pixel-centre magnet` и `Find marker centre…` решают разные задачи и могут
включаться независимо.

### `Pixel-centre magnet`

Магнит не анализирует содержимое изображения. Он переносит координату в центр
того пикселя, внутри которого находится точка:

```text
x → ⌊x⌋ + 0,5
y → ⌊y⌋ + 0,5
```

При включении магнит сразу обрабатывает текущую активную точку. Пока флажок
установлен, он применяется к каждой новой точке `Scatter` или `Curve`, а также
после перемещения активной точки мышью, стрелками или через таблицу. Опоры
калибровки и границы области магнит не изменяет.

Магнит полезен, когда требуется указать центр конкретного растрового пикселя.
Для маркера или штриха чётной ширины его обычно следует выключить: истинный
геометрический центр может лежать между пикселями. Кнопка `Snap active now`
выполняет однократную привязку выбранной точки.

### `Find marker centre…`

Поиск центра анализирует локальное окно вокруг активной точки. Фон оценивается
по границе окна, после чего выделяется связный объект рядом с исходным кликом.
Алгоритм проверяет размер, компактность, распределение по направлениям и
центральную симметрию. Если через маркер проходит одна приблизительно прямая
линия, алгоритм пытается отделить её перед вычислением центра.

Кандидат отклоняется, если сигнал слишком слаб, объект обрезан окном, похож на
обычный участок линии, содержит несколько длинных направлений или выраженно
асимметричен. При успешном поиске кандидат сначала показывается на изображении
и в лупе вместе со смещением и оценкой надёжности. По умолчанию сохраняется
исходная точка; новая координата применяется только после нажатия
`Use candidate`.

Подтверждённый центр может оставаться между пикселями, даже если магнит включён:
результат поиска намеренно не округляется. Радиус нужно выбирать так, чтобы
маркер целиком помещался в окно, а соседние подписи и маркеры — нет.

Флажок `Auto centre suggestion` запускает тот же поиск после создания каждой
новой точки. Он по-прежнему требует подтверждения и не выполняет пакетное
распознавание серии.

![Проверка центра маркера в режиме Scatter](docs/images/scatter-precision.png)

Сводный порядок проверки рамки, опор и точек приведён в
[руководстве по точности](docs/ACCURACY_GUIDE_RU.md).

## Режим Scatter

`Scatter` хранит независимые наблюдения. Каждая точка имеет точную
пиксельную позицию с плавающей запятой; отображаемый текст таблицы не является
источником данных для экспорта.

Доступны четыре способа установки:

- `Free` сохраняет выбранное положение без привязки к опорам;
- `Lock X` привязывает X к ближайшей X-опоре и оставляет свободным Y;
- `Lock Y` привязывает Y к ближайшей Y-опоре и оставляет свободным X;
- `Lock X+Y` проверяет обе оси независимо и фиксирует каждую найденную
  привязку.

Привязка выполняется только в пределах `Max anchor distance`. Она использует
введённые калибровочные опоры, а не автоматически продолженную регулярную
сетку. Если подходящей опоры рядом нет, соответствующая координата остаётся
свободной.

Окно `Style Points` меняет форму и размер выбранных и следующих новых точек, а
также вид активной точки. Несколько серий хранятся в отдельных вкладках.

## Режим Curve

`Curve` предназначен для однозначной зависимости `y(x)`. Пользователь задаёт
контрольные точки, а приложение строит через них гладкую кривую. Точки
сортируются по X; совпадающие или численно неразличимые X считаются ошибкой.
Вертикальные участки, петли и несколько значений Y при одном X этим режимом не
поддерживаются.

![Контрольные точки и интерполированная кривая](docs/images/curve-digitizing.png)

### Как строится кривая

Используется PCHIP — кусочно-кубический эрмитов интерполянт, сохраняющий форму
данных. Это не один полином высокой степени по всем точкам. На каждом интервале
между соседними X строится свой кубический полином, совпадающий со значениями
на концах. Производные в узлах выбираются по соседним наклонам так, чтобы на
монотонном участке не появлялись новые экстремумы.

Кривая проходит через все контрольные точки. Её первая производная непрерывна,
а непрерывность второй производной не требуется. По сравнению с обычным
кубическим сплайном это уменьшает риск ложных колебаний и выбросов между
монотонными данными. За пределами крайних X экстраполяция не выполняется.

Интерполяция строится в координатах осей, а не в пикселях. Для каждой
логарифмической оси соответствующая координата сначала преобразуется через
`log10`; после вычисления кривой применяется обратное преобразование. Поэтому
видимая линия согласована с выбранным типом шкалы.

Предварительный просмотр и основной лист серии при экспорте используют один и
тот же интерполятор. Параметр `Export dx` задаёт расстояние между экспортируемыми
отсчётами в исходных единицах X, в том числе для логарифмической оси. Обе
крайние контрольные точки включаются всегда. Общее число экспортируемых точек
ограничено одним миллионом, чтобы ошибочно малый шаг не исчерпал память.

Окно `Style Points` управляет контрольными точками. Окно `Curve Style` меняет
цвет, толщину и вид линии активной кривой. Эти параметры влияют только на
отображение и не меняют интерполяцию.

## Экспорт в Excel

Кнопка `Export to Excel` создаёт книгу `.xlsx` со следующими листами:

- `Series_1`, `Series_2` и далее — данные каждой серии, отсортированные по X;
- `Combined` — серии, приведённые к общей колонке X;
- `Metadata` — путь к исходному файлу, дата, типы шкал и сведения о сериях.

Способ построения листа `Combined` выбирается перед экспортом:

- `Union X` использует объединение имеющихся X. Для `Scatter` заполняются
  только действительно измеренные позиции; непрерывные серии приводятся к
  общей сетке;
- `Uniform grid` создаёт равномерную общую сетку, но не интерполирует
  `Scatter`. Поэтому для дискретной серии заполняются только точно совпавшие X;
- `Interpolation` создаёт равномерную сетку и линейно интерполирует все серии,
  включая `Scatter`, внутри их диапазонов.

Последний вариант создаёт вычисленные значения между дискретными наблюдениями
и должен выбираться осознанно. На отдельном листе непрерывной серии сначала
вычисляется PCHIP-выборка с шагом `Export dx`; при переносе на отличающуюся
сетку листа `Combined` между этими отсчётами используется линейная
интерполяция.

## Файлы проекта

`Save project` сохраняет файл `.digitizer`. В него входят границы области,
опоры и типы шкал, точные пиксельные позиции, серии, стили и настройки
экспорта. Незавершённую калибровку также можно сохранить и продолжить позже.

Само изображение в проект не встраивается. В `.digitizer` хранится путь к
исходному файлу, поэтому для полноценного открытия проекта изображение должно
оставаться доступным по тому же пути. Один файл `.digitizer` без исходного
изображения не является переносимой копией работы.

## Ограничения

- Калибровка осевая: `X` зависит только от горизонтальной пиксельной
  координаты, `Y` — только от вертикальной. Поворот, скос и перспектива не
  компенсируются.
- Автоматический поиск области рассчитан на прямоугольную рамку с
  горизонтальными и вертикальными сторонами. Открытые или повёрнутые оси
  требуют ручной установки.
- `Curve` описывает только однозначную функцию `y(x)`.
- Поиск центра работает с одной активной точкой и всегда требует контроля.
  Пакетного распознавания маркеров и автоматического извлечения кривых нет.
- Диагностические остатки калибровки не учитывают качество изображения,
  толщину линии данных и субъективность выбора её центра.
- Повторное JPEG-сжатие, малое разрешение и размытые линии ограничивают
  достижимую точность независимо от используемых инструментов.

## Архитектура проекта

Код разделён на слои с разной ответственностью:

```text
src/core/     численные алгоритмы, обработка изображения, экспорт и проекты
src/models/   структуры состояния, калибровки и серий
src/gui/      интерфейс PySide6, режимы работы и графические наложения
tests/        модульные и интеграционные проверки
```

Численные части не зависят от элементов интерфейса. Калибровку, интерполяцию,
поиск центра маркера и экспорт можно проверять и развивать отдельно. Интерфейс
собирает эти инструменты в последовательность `Crop` → `Ref Points` →
`Data Points`, а модели хранят состояние между ними.

При добавлении нового инструмента предпочтительно сначала оформить его как
небольшой модуль с явными входными и выходными данными, затем подключить к
интерфейсу и покрыть граничные случаи тестами. Такой порядок уменьшает связь с
PySide6 и позволяет использовать алгоритм вне настольного приложения.

Подробная карта модулей и потока состояния находится в
[описании архитектуры](docs/ARCHITECTURE_RU.md), правила подготовки изменений —
в [CONTRIBUTING.md](CONTRIBUTING.md).

## Проверка изменений

Для запуска тестов установите зависимости разработки и выполните:

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python -m compileall -q src tests
```

Наиболее чувствительные участки — вырожденные и логарифмические калибровки,
рамки чётной толщины, повторяющиеся X в `Curve`, границы поискового окна
маркера, сохранение незавершённого проекта и соответствие экранной кривой
экспортируемым значениям.
